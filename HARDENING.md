## Findings Fixed

### script-injection (severity: high)

Multiple ${{ inputs.* }} expressions are directly interpolated inside run: blocks (nushell scripts) across four composite action steps. Rule (a) violation: YAML template substitution occurs before the shell processes the string, so a calling workflow that supplies a malicious input value (e.g. inputs.version containing nushell metacharacters or command-injection payloads) can execute arbitrary code. Affected expressions include: `clang-format-${{ inputs.version }}`, `clang-tidy-${{ inputs.version }}`, `${{ inputs.version }}` passed to llvm_install.sh, `llvm@${{ inputs.version }}`, `'${{ inputs.verbosity }}'`, `"${{ inputs.tidy-checks }}"`, `"${{ inputs.style }}"`, `'${{ runner.os }}'`, and all `${{ inputs.* }}` entries in the args list of the Run cpp-linter step. These must be moved to env: variables and referenced as `$env.VAR_NAME` inside the nushell scripts.

### unsafe-shell (severity: high)

In the 'Setup cpp-linter dependencies' step, a remote installer script is fetched from astral.sh via `http get --raw --redirect-mode follow $uv_installer_url` and the result is stored in `$installer`, then executed with `$installer | ^sh` (on non-Windows) or `^powershell -ExecutionPolicy ByPass $installer` (on Windows). This is the nushell equivalent of `curl https://... | sh` — piping remote content directly to a shell interpreter without first saving it to a file and verifying its integrity. A compromised or MitM'd astral.sh could deliver a malicious payload.
